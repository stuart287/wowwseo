# Technical Audit References

This folder contains the operating materials for the `technical-audit` skill.

## Distilled References

- `report-structure.md`: Woww technical audit section order and report expectations.
- `data-sources.md`: common crawl, Google, live-check, migration, sitemap, and PageSpeed evidence sources.
- `recommendation-style.md`: severity, wording, and practical recommendation patterns.
- `normalization-schema.md`: standard fields and mapping rules for crawl/export normalisation.
- `source-pack-guide.md`: local source-pack structure and patterns from completed Woww technical audits.

## Local Source Packs

Use `source-packs/` when the task needs completed audit examples, workbook structures, migration evidence, sitemap planning examples, PageSpeed evidence, or report-style examples.

- `Technical Audit - Pikeland Property Group/`: local/property-service technical audit example with completed report, URL crawl export, redirects, 404s, duplicate content, HTTP internal links, orphan pages, internal links to redirects/404s, redirect chains, and current/proposed sitemap workbook.
- `Technical Audit - Paradise Games/`: gaming/iGaming technical plus migration audit example with completed report, URL crawl export, redirects, 404s, internal HTTP links, orphan pages, redirect chains, PageSpeed migration workbook, migration notes, robots draft, sitemap drafts, proposed sitemap docs, and migration checklist.

## Handling Rules

- Read this README before selecting local references.
- Use `source-pack-guide.md` before opening individual DOCX/XLSX files.
- Treat each source pack as client-specific evidence and never mix findings between clients.
- Inspect workbook sheet names and header rows before using data.
- Treat completed audit DOCX files as structure, tone, evidence selection, and report-style examples unless the user is updating that exact audit.
- Treat migration notes, sitemap drafts, robots drafts, and proposed sitemap files as planning/implementation evidence, not as crawl proof.
- Clearly label missing, stale, mismatched, duplicated, template-leftover, or suspicious source data.
