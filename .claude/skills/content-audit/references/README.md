# Content Audit References

This folder contains the operating materials for the `content-audit` skill.

## Distilled References

- `source-data-map.md`: common crawl, keyword, linking, content analysis, and report source files.
- `audit-judgement-rules.md`: severity rules, thresholds, recommendation patterns, and QA guidance.
- `source-pack-guide.md`: local source-pack structure and patterns from completed Woww content audits.

## Local Source Packs

Use `source-packs/` when the task needs completed audit examples, workbook structures, source-data naming patterns, report structure, or evidence-handling examples.

- `Paradise Games - Content Audit/`: gaming/lotto content audit example with completed report, crawl exports, keyword research brackets, existing keyword data, cannibalisation, keyword intersect, seed-term brainstorming, and a content strategy workbook.
- `Content Audit - Pikeland Property Group/`: local/property-service content audit example with completed report, crawl exports, qualitative content analysis, keyword research brackets, existing keyword data, cannibalisation, keyword intersect, and seed-term brainstorming.

## Handling Rules

- Read this README before selecting local references.
- Use `source-pack-guide.md` before opening individual DOCX/XLSX files.
- Treat each source pack as client-specific evidence and never mix findings between clients.
- Inspect workbook sheet names and header rows before using data.
- Treat completed audit DOCX files as structure, tone, evidence selection, and report-style examples unless the user is updating that exact audit.
- Treat keyword research and strategy workbooks as opportunity evidence, not proof that existing pages are already optimised.
- Clearly label missing, stale, mismatched, or suspicious source data.
